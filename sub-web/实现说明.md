# sub-web 实现说明

本文梳理 sub-web 的核心逻辑，写给需要维护或修改代码的人。部署方法、接口参数和外部配置写法见 [README.md](README.md)。

## 1. 总体结构

整个服务是一个 Cloudflare Pages 项目：`public/` 是静态网页，`functions/` 是 Pages Functions，两者同域名部署。
转换逻辑全部在 `src/` 里，运行时只依赖一个第三方库 `yaml`，不调用任何外部 subconverter。

| 路由 | 文件 | 作用 |
| --- | --- | --- |
| `/` | `public/index.html`、`public/app.js` | 网页：拼装订阅链接、预览转换结果 |
| `/sub` | `functions/sub.js` → `src/handler.js` | 转换接口，参数与 subconverter 兼容 |
| `/ruleset` | `functions/ruleset.js` → `src/ruleset.js` | 规则集中转，供 rule-providers 下载 |
| `/version` | `functions/version.js` | 返回版本号，并告诉网页是否需要访问令牌 |

`/sub` 与 `/ruleset` 共用 `src/http.js` 里的响应构造和访问令牌校验。

`functions/` 下的文件只做路由转发，逻辑都在 `src/` 中，因此可以直接在 Node 里调用和测试，不依赖 Cloudflare 运行时。

网页和接口同源，带来两个好处：

- 浏览器预览转换结果时没有跨域问题，能直接读取 `X-Node-Count` 等响应头。
- 不需要配置域名：网页用 `location.origin` 拼订阅链接，后端用请求地址的 origin 拼规则集中转地址，部署到哪个域名就用哪个域名。

## 2. 一次 /sub 请求的处理流程

```
请求 /sub?target=clash&url=...&config=...
  │
  ├─ handler.js     校验访问令牌 → parseOptions 解析参数
  │
  ├─ convert.js     下载外部配置（config.js 解析 ini）
  │                 并行下载：订阅 ×N、clash_rule_base、规则集（仅 expand=true）
  │
  ├─ parsers/       识别订阅格式 → 每条节点解析为 mihomo 代理对象
  ├─ nodes.js       筛选 → 重命名 → 类型前缀 → Emoji → 排序 → 名称去重 → udp/tfo/scv 覆盖
  │
  ├─ target=mixed   generators/links.js 转回分享链接 → Base64 → 返回
  ├─ list=true      generators/clash.js 只输出 proxies → 返回
  │
  ├─ groups.js      按 custom_proxy_group 生成策略组，消除循环引用
  ├─ rules.js       按 ruleset 生成规则：展开为规则行，或生成 rule-providers
  ├─ generators/clash.js  组装 YAML，警告写进文件开头的注释
  │
  └─ handler.js     加上响应头（节点数、警告、流量信息、文件名）后返回
```

下载外部配置必须先完成，因为后续要下载什么（规则集、基础配置）取决于配置内容。其余下载全部并行。

## 3. 各环节细节

### 3.1 参数解析（`convert.js` 的 `parseOptions`）

- `target`：`clash`、`clashmeta`、`mihomo` 等统一为 `clash`；`mixed`、`v2ray`、`base64`、`shadowrocket` 统一为 `mixed`。其他值返回 400。
- `url`：用 `|` 或换行拆成多个来源。以 `http(s)://` 开头的当作订阅地址下载，其余当作直接粘贴的节点内容。
- 三态参数：`emoji`、`udp`、`tfo`、`scv` 不传时为 `undefined`，表示「不覆盖」，保留订阅或外部配置里的原设置。
- `expand`：接口默认 `true`，与 subconverter 保持一致；网页默认传 `false`，原因见第 7 节。
- `relay`：记录请求的 origin 和 `token`，生成 rule-providers 地址时使用。

### 3.2 下载（`convert.js` 的 `createFetcher`）

所有远程内容都经过同一个下载函数：只允许 http / https，跟随重定向，内容超过 20 MB 时报错。

| 内容 | User-Agent | 超时 | Cloudflare 边缘缓存 |
| --- | --- | --- | --- |
| 订阅 | `ua` 参数，默认 `clash.meta` | 20 秒 | 不缓存 |
| 外部配置 | `clash.meta` | 15 秒 | 5 分钟 |
| `clash_rule_base` | `clash.meta` | 15 秒 | 1 小时 |
| 规则集 | `clash.meta` | 15 秒 | 1 小时 |

订阅默认使用 `clash.meta` 作为 User-Agent，是因为很多机场按 UA 决定返回内容，这个 UA 通常能拿到包含 vless、hysteria2 等节点的完整 mihomo 订阅。

### 3.3 识别订阅格式（`parsers/subscription.js`）

按以下顺序判断：

1. 去掉 BOM。如果内容里没有 `://`，尝试按 Base64 解码；解码结果包含 `://` 或 `proxies:` 时才采用，否则保持原文。
   随后用 `sanitizeText` 清理控制字符和 Unicode 换行符（原因见第 8 节）。YAML 解析保留 `yaml` 库默认的别名展开上限，避免恶意订阅用嵌套别名耗尽资源。
2. 有 `proxies:` 行：按 Clash YAML 解析，保留同时有 `name`、`type`、`server`、`port` 的节点，字段原样沿用。
3. 以 `{` 开头：按 SIP008 JSON 解析为 ss 节点。
4. 其他：逐行当作分享链接解析。注释行跳过；无法识别的协议只计数；格式错误的节点逐条记警告，不影响其他节点。

### 3.4 解析节点链接（`parsers/links.js`）

**内部统一使用 mihomo 的代理对象格式**，字段名与 Clash 配置一致（如 `ws-opts`、`reality-opts`）。这样 Clash YAML 订阅里的节点可以原样沿用；输出 Clash 时直接写出，输出分享链接时再反向转换。

链接解析没有用 `URL` 类，而是自己实现了 `parseStdUri`（在 `utils.js` 中），原因是：

- `URL` 对 `vless://` 这类非标准协议的处理不一致，例如会吞掉默认端口。
- 查询参数用自己的 `QueryParams` 解析，把 `+` 当字面字符。密码和 Reality 公钥里常有 `+`，`URLSearchParams` 会把它变成空格。`/sub` 和 `/ruleset` 的接口参数同样用它解析，所以订阅地址、正则、访问令牌里的 `+` 都按字面量处理；网页生成链接时用 `encodeURIComponent` 编码，空格是 `%20`。
- 地址拆分要支持 `[IPv6]:端口`，以及 Hysteria2 的多端口写法 `host:443,20000-30000`。

各协议支持的写法：

| 协议 | 支持的写法 |
| --- | --- |
| ss | SIP002（用户信息为 Base64 或明文，含 2022 系列加密）、旧式整体 Base64；插件 obfs、v2ray-plugin、shadow-tls |
| ssr | 标准 Base64 链接；字段从右往左取，兼容 IPv6 地址 |
| vmess | v2rayN JSON、Shadowrocket 格式、Xray 标准 URI（`@` 出现在 `?`、`#` 之前时判定为标准 URI） |
| vless / trojan | TLS、Reality；传输层 tcp、ws、httpupgrade、grpc、h2、xhttp，以及 tcp + http 伪装 |
| hysteria2（hy2）/ hysteria / tuic / anytls | 标准 URI；tuic 同时支持 v5（uuid + 密码）和 v4（token） |
| socks5 / wireguard | 标准 URI；socks 兼容 v2rayN 的 Base64 用户信息 |

解析结果经过 `prune` 去掉空字段，保持输出整洁。

### 3.5 外部配置（`config.js`）

只解析 subconverter 的 ini 格式，读取 `ruleset`、`custom_proxy_group`、`enable_rule_generator`、`overwrite_original_rules`、`clash_rule_base`、`exclude_remarks`、`include_remarks`、`rename`、`emoji`、`add_emoji`、`remove_old_emoji`，其他键忽略。

- `ruleset` 拆成三种：内联规则（`[]GEOIP,CN`）、远程规则集（可带 `clash-domain:` 等前缀和更新间隔）、无法解析（记警告）。
- `custom_proxy_group` 按反引号拆分。测速类分组（url-test、fallback、load-balance）从成员里找出第一个 http 地址作为测速地址，它后面一项是「间隔,超时,容差」。
- 发现 YAML / TOML 格式的配置时直接返回 400，避免当成 ini 解析出错误结果。

### 3.6 节点后处理（`nodes.js`）

固定顺序如下，顺序会影响结果：

1. **筛选**：外部配置和 URL 参数中的 `exclude` 和 `include` 一起生效。排除优先；有包含条件时，只保留至少匹配一条的节点。匹配的是订阅里的原始名称。
2. **重命名**：先应用外部配置的 `rename`，再应用 URL 参数的 `rename`。
3. **类型前缀**：`append_type=true` 时在名称前加 `[VMess]` 等。
4. **Emoji**：先去掉名称开头已有的 Emoji，再按地区关键字加国旗。`emoji` 参数优先，其次是外部配置的 `add_emoji` / `remove_old_emoji`，都没有时默认开启。外部配置里写了 `emoji=` 规则时，完全替代内置的地区表。
5. **排序**：`sort=true` 时按中文排序规则排序。
6. **名称去重**：重名节点加 ` 2`、` 3` 后缀；节点名也不能与策略组名或 `DIRECT` 等内置策略重名，否则 Clash 会认错引用。
7. **统一覆盖**：传了 `udp`、`tfo` 时写入所有节点；传了 `scv` 时只写入使用 TLS 的协议。

内置地区表（`emoji.js`）按顺序匹配，先命中先生效。容易被包含的名称要放在后面，例如「印度尼西亚」排在「印度」前面。两位国家代码要求前后都不是字母，避免把单词里的字母误判为国家代码。

### 3.7 策略组（`groups.js`）

每个 `custom_proxy_group` 的成员按以下规则展开：

- `[]名称`：先看是不是 `DIRECT`、`REJECT` 等内置策略（不区分大小写），再看是不是其他策略组或节点名，都不是则忽略并警告。
- 其他内容按正则匹配节点名，按订阅里的节点顺序加入。支持 subconverter 常见的 `(?i)` 前缀。
- `!!GROUP=` 等 subconverter 专有写法不支持，忽略并警告。

然后做三项修正，保证 mihomo 能加载：

1. **自引用**：分组引用自己时直接跳过。
2. **循环引用**：按定义顺序深度优先遍历，遇到正在访问的分组就删掉这条引用并警告，因此先定义的分组保留它的引用。
   例如「🚀 节点选择」引用「🚀 手动切换」，「🚀 手动切换」又引用「🚀 节点选择」，结果删掉的是后者的引用（仓库里的 `clash.ini` 曾有这个问题，已修正）。不修正的话，mihomo 会报 `loop is detected in ProxyGroup` 并拒绝加载。
3. **空分组**：没有任何成员的分组放入 `DIRECT`，比如订阅里没有韩国节点时的「🇰🇷 韩国节点」。

另外，非标准的分组类型改为 `select` 并警告；测速超时小于 1000 时视为秒，换算为 mihomo 使用的毫秒。

### 3.8 规则（`rules.js`、`convert.js` 的 `buildRules`）

**规则从哪里来**（只针对完整 Clash 配置）：

| 条件 | 使用的规则 |
| --- | --- |
| 外部配置开启了 `enable_rule_generator` 且有 `ruleset` | 按 `ruleset` 生成；`overwrite_original_rules=false` 时接在 `clash_rule_base` 原有规则之后 |
| 否则，`clash_rule_base` 里有规则 | 沿用基础配置的规则 |
| 否则，外部配置定义了策略组 | 只有一条 `MATCH,第一个策略组` |
| 都没有 | 局域网和中国 IP 直连，其余走「🚀 节点选择」 |

**逐条处理 `ruleset`**，保持原顺序，因为 Clash 按顺序匹配：

- 指向的策略组不存在：跳过并警告。可用的策略包括策略组、内置策略和节点名。
- 内联规则：规范化后直接加入。
- `expand=true`：使用已下载的规则集内容，每行规范化后附加策略组。
- `expand=false`：为每个规则集地址生成一个 rule-provider，规则写成 `RULE-SET,名称,策略组`。

**规范化单行规则**（`normalizeRule`）。各家规则列表写法不一，统一转成 mihomo 能识别的格式：

| 原始写法 | 结果 |
| --- | --- |
| 注释、`payload:` | 忽略 |
| `- '+.google.com'`（Clash YAML 列表项） | `DOMAIN-SUFFIX,google.com` |
| `10.0.0.0/8`、`2001:db8::/32` | `IP-CIDR,…`、`IP-CIDR6,…` |
| `example.com` | `DOMAIN,example.com`（精确匹配，与 Surge DOMAIN-SET 和 Clash domain 列表的含义一致） |
| `*.example.com` | `DOMAIN-WILDCARD,*.example.com` |
| `HOST-SUFFIX,a.com`、`FINAL` 等其他客户端写法 | 转为 `DOMAIN-SUFFIX,a.com`、`MATCH` 等 |
| `IP-CIDR,1.0.0.0/8,Proxy,no-resolve` | 丢掉列表里自带的策略名，保留 `no-resolve` |
| `AND`、`OR`、`NOT` 逻辑规则 | 只保留括号内的部分（去掉列表自带的策略名），子规则类型按别名表转换；任一子规则不受支持则整条丢弃 |
| 列表中的 `MATCH`、`FINAL`、`RULE-SET`、`SUB-RULE` | 丢弃并计数：`MATCH` 会让后面的规则全部失效，`RULE-SET` 指向的 provider 并不存在 |
| `URL-REGEX`、`USER-AGENT` 等 mihomo 不支持的类型 | 丢弃，按类型计数，汇总成一条警告 |

规范化结果分成 `head`（匹配条件）和 `tail`（`no-resolve` 等选项），策略组插在两者之间，即 `IP-CIDR,1.0.0.0/8,🎯 全球直连,no-resolve`。

**去重**：匹配条件完全相同的规则只保留第一条。Clash 按顺序匹配，后面的同条件规则永远不会命中，删掉不影响行为，还能减小配置。例如 `clash.ini` 里 `SteamCN.list` 先后分给「🎯 全球直连」和「🎮 游戏平台(steamCN)」，第二次分配不会生效，在 `expand=false` 时同样只保留第一条 `RULE-SET`。

**rule-provider 命名与地址**（`buildProvider`）：名称取规则集文件名（去扩展名、替换特殊字符，重名加 `_2`）；地址指向本站的 `/ruleset?url=原地址`，带上规则集类型和访问令牌；`behavior` 统一为 `classical`，`format` 统一为 `text`，因为 `/ruleset` 总是输出 classical 文本。更新间隔取 `ruleset` 行里写的值，默认 86400 秒。

### 3.9 输出（`generators/`）

**Clash YAML**（`clash.js`）：

- 以 `clash_rule_base` 为基础；没有时用内置的精简配置（端口 7890、规则模式、本机控制端口 9090）。基础配置里的 `proxies`、`proxy-groups`、`rule-providers`、`rules` 会被替换，`rule-providers` 与新生成的合并。
- 节点字段按 `name`、`type`、`server`、`port` 在前的顺序输出，便于阅读。
- 除 `rules` 外的部分用 `yaml` 库按 YAML 1.1 规则输出，避免 `yes`、`on`、`0755` 这类字符串被当成布尔值或数字。
- **`rules` 逐行拼接输出**，不经过 `yaml` 库。上万条规则走 `yaml` 库需要几十毫秒，逐行拼接快一个数量级。含 `: `、` #` 等会破坏 YAML 的字符时，改用双引号转义输出。
- 文件开头写入生成时间、节点 / 策略组 / 规则数量和全部警告，方便在客户端里排查。

**分享链接**（`links.js`）：把代理对象转回各协议的链接，再整体 Base64 编码。ss 的 shadow-tls 插件、TUIC v4 token 认证、HTTP 等没有通用链接格式的节点会被跳过并警告。测试里验证了「链接 → 代理对象 → 链接 → 代理对象」前后一致。

### 3.10 响应（`handler.js`）

| 响应头 | 内容 |
| --- | --- |
| `subscription-userinfo` | 第一个带此信息的订阅返回的流量和到期时间，原样透传给客户端 |
| `X-Node-Count` | 最终节点数 |
| `X-Convert-Warnings` | 警告列表的 JSON，经 URL 编码后只含 ASCII。每条截断到 200 字，超过 6000 字符时减半列表，避免响应头过大 |
| `Content-Disposition` | 传了 `filename` 时设置，客户端用它显示配置名 |
| `Cache-Control: no-store` | 订阅结果不缓存，每次都实时转换 |

## 4. /ruleset 中转（`ruleset.js`）

`expand=false` 时，配置里的 rule-providers 都指向本站的 `/ruleset`，由客户端按更新间隔各自下载。处理过程：

1. 校验访问令牌。
2. 下载原规则集（边缘缓存 1 小时），下载失败返回 502。
3. 用与展开模式相同的 `parseRuleList` 规范化，只输出不含策略组的规则行；不支持的类型写在开头的注释里。
4. 响应 `Cache-Control: public, max-age=3600`。

这样做的好处：

- 客户端只要能访问本站就能更新规则，不需要直连 GitHub。
- mihomo 收到的规则已经过滤掉了它不支持的类型，加载时不会刷警告。
- 每次只处理一个规则集，CPU 和子请求数都很少，不受第 7 节的限制。

本地验证时，mihomo 通过 `/ruleset` 成功加载了 `clash.ini` 的全部 32 个规则集，共 15775 条规则，没有警告。

## 5. 网页（`public/app.js`）

网页本身不做转换，只负责拼链接和展示结果：

- **生成链接**：把表单转成 `/sub` 的参数，域名取 `location.origin`。`emoji`、`expand` 总是显式传递；`udp`、`scv`、`tfo`、`sort`、`append_type` 只在勾选时传，不勾选表示保留订阅原设置。「Clash 仅节点」转换为 `target=clash&list=true`。
- **远程配置**：手动输入，没有预设，默认留空。输入框里的仓库地址只是提示文字。
- **本地保存**：选项保存在浏览器的 `localStorage` 里，下次打开自动恢复。**订阅链接和远程配置地址不保存**；访问令牌只放在 `sessionStorage`，刷新页面还在，关闭标签页即清除。
- **预览**：直接请求生成的链接，显示节点数、大小、耗时、流量信息和警告；`mixed` 结果先解码 Base64 再显示；超过 300 KB 只显示前面部分。
- **还原表单**：粘贴已有链接，按参数回填表单。链接里没有 `expand` 时按接口默认值视为 `true`。
- **后端检测**：打开页面时请求 `/version`，响应头 `X-Token-Required: 1` 时显示访问令牌输入框。
- **导入 Clash**：跳转到 `clash://install-config?url=…`，由本机的 Clash 客户端接管。

## 6. 错误与警告

原则是：**能继续转换的问题记为警告，并写进配置文件开头；无法得到可用结果时才返回错误。**

| 情况 | 处理 |
| --- | --- |
| 缺少 `url`、不支持的 `target` | 400 |
| 外部配置下载失败、格式不是 ini | 400 |
| 部分订阅下载失败、部分节点解析失败 | 警告，继续用其余节点 |
| 所有来源都没有解析出节点 | 400，并附上全部警告 |
| 筛选后没有节点 | 400 |
| 规则集下载失败、规则指向不存在的策略组、不支持的规则类型 | 警告，跳过对应内容 |
| 策略组引用不存在、循环引用、类型不支持、正则无效 | 警告，自动修正 |
| `clash_rule_base` 加载失败 | 警告，改用内置基础配置 |
| 访问令牌错误 | 403 |
| 其他意外异常 | 500，并在 Cloudflare 日志中打印错误 |

## 7. Cloudflare 限制与性能取舍

Cloudflare 免费版的关键限制：每次请求 CPU 时间 10 ms（偶尔超出可以容忍，持续超出返回 1102 错误）、最多 50 个子请求、同时最多 6 个连接等待响应。

以 `clash.ini`（32 个规则集，约 1.55 万条规则）和 150 个节点为例，在本机 Node 上测得的单次转换 CPU 时间如下，Cloudflare 上的实际值会有出入：

| 模式 | CPU 时间 | 子请求数 |
| --- | --- | --- |
| `expand=true`（展开规则） | 约 18–48 ms（冷启动约 77 ms） | 订阅数 + 外部配置 + 基础配置 + 去重后的规则集数，`clash.ini` 为 34 |
| `expand=false`（rule-providers） | 约 6–12 ms | 订阅数 + 外部配置，`clash.ini` 为 2 |

因此：

- **网页默认生成 `expand=false` 的链接**，在免费版上也能稳定运行。
- 接口默认仍为 `expand=true`，以兼容 subconverter 的链接写法。免费版上使用这种链接会频繁超出 CPU 限额；付费版没有这个问题。
- 为降低展开模式的耗时做了两项优化：`normalizeRule` 尽量避免正则和数组操作（解析 1.5 万条规则从约 20 ms 降到约 9 ms），以及 `rules` 逐行拼接输出（见 3.9）。
- 网络请求不计入 CPU 时间，展开模式下载 32 个规则集的等待时间不受 10 ms 限制，只影响响应速度。

## 8. 安全

- **访问令牌**：设置 `ACCESS_TOKEN` 后，`/sub` 和 `/ruleset` 都要求带 `token` 参数；网页和 `/version` 仍可公开访问。不设置令牌时，任何人都可以让你的 Cloudflare 去下载任意 http(s) 地址。返回的是转换后的内容，不是原文，但 `/ruleset` 会把不含逗号的行原样变成 `DOMAIN-SUFFIX,行内容`。公开部署时建议设置令牌。
- **链接即凭据**：生成的订阅链接包含机场订阅地址（其中通常带订阅令牌）和访问令牌；`expand=false` 时，配置里每个 rule-provider 地址也带访问令牌。转发链接或配置文件，就等于交出了这些令牌。
- **数据去向**：订阅内容经过 Cloudflare，在 Functions 内存中转换后直接返回，不写入任何存储，也不缓存。只有意外异常时会在日志里打印错误信息，不打印订阅内容。
- **浏览器存储**：网页把选项存在 `localStorage`，访问令牌只存在 `sessionStorage`（关闭标签页即清除），订阅链接和远程配置地址不存。
- **防止订阅内容注入配置**：mihomo 的 YAML 解析器把 U+2028、U+2029、U+0085 也当作换行，而 JS 不会。订阅里的节点名若藏有这些字符，写进文件开头的警告注释或节点字段后，会在 mihomo 眼里提前换行，后面的文字变成配置的顶层键（例如注入 `dns:` 劫持解析）。因此 `sanitizeText` 在订阅和外部配置进入流水线时就把这些字符连同其他控制字符替换成空格，`renderHeader` 和 `generateClash` 输出前再清理一遍。`handler.test.js` 里有对应的回归测试。

## 10. 已知限制

- 只支持输出 Clash（mihomo）和通用 Base64，不支持 Surge、Quantumult X、Loon、sing-box。
- 外部配置只支持 ini 格式；`!!GROUP=` 等 subconverter 专有写法会被忽略。
- 内置基础配置不含 DNS、TUN 等设置，需要时在外部配置里用 `clash_rule_base` 指定基础配置。
- Emoji 按关键字判断地区。「港」「台」「美」这类单字关键字可能误判，必要时在外部配置里用 `emoji=` 规则覆盖。
- `clash-domain` 规则集里 `.example.com` 的写法会转为 `DOMAIN-SUFFIX`，同时匹配根域名，比原意稍宽。
- 订阅不缓存，客户端每次更新都会重新请求机场。
- 不提供短链接和配置上传。
